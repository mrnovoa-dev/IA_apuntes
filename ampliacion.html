1. Diseñar programas que se puedan cambiar

Un programa de clase cabe en una pantalla. Uno de verdad tiene miles de líneas, lo tocan varias personas durante años, y cada cambio puede romper otra cosa. Los principios de diseño son consejos para que cambiar sea barato.

Principios SOLID

Letra Principio En una frase Señal de que falla
S Responsabilidad única Cada clase o función tiene un motivo para cambiar «Esta función calcula la nota, la redondea, la formatea y la envía»
O Abierto/cerrado Añadir comportamiento sin tocar lo que ya funciona Cada opción nueva añade otro elif en el mismo sitio
L Sustitución de Liskov Una clase hija sirve en cualquier sitio donde sirva la madre La hija lanza «no implementado» en un método de la madre
I Segregación de interfaces Mejor varias interfaces pequeñas que una enorme Una clase tiene que implementar métodos que no usa
D Inversión de dependencias Depender de lo que algo hace, no de qué es El código crea dentro el objeto de correo y no se puede probar sin enviar correos

Un ejemplo con tres de ellos. El boletín de notas no sabe cómo se envía (D) ni cómo se redondea (O): se le pasa. Así, en las pruebas se usa un envío «de mentira» y para añadir un redondeo nuevo basta con añadir una entrada al diccionario:

from typing import Protocol, Callable

class Envio(Protocol):
    def enviar(self, destino: str, texto: str) -> None: ...

class PorCorreo:
    def enviar(self, destino, texto): print(f"[correo a {destino}] {texto}")

class EnPantalla:                                   # para probar sin enviar nada
    def __init__(self): self.enviados = []
    def enviar(self, destino, texto): self.enviados.append((destino, texto))

def media(notas): return sum(notas) / len(notas)
REDONDEOS: dict[str, Callable[[float], float]] = {     # estrategias intercambiables
    "normal": lambda x: round(x, 1),
    "medio_punto": lambda x: round(x * 2) / 2,
}

class Boletin:
    def __init__(self, envio: Envio, redondeo="normal"):
        self.envio, self.redondear = envio, REDONDEOS[redondeo]
    def generar(self, alumno, notas):
        self.envio.enviar(alumno, f"Media: {self.redondear(media(notas))}")

Boletin(PorCorreo()).generar("Uxía", [7, 8.5, 6.25])           # [correo a Uxía] Media: 7.2
prueba = EnPantalla()
Boletin(prueba, "medio_punto").generar("Brais", [7, 8.5, 6.25])
print(prueba.enviados)                                          # [('Brais', 'Media: 7.0')]

Protocol dice qué métodos tiene que tener un envío, sin obligar a heredar de nada: es el tipado de pato de la teoría 14.14, escrito para que lo comprueben las herramientas de tipos.

DRY, KISS y YAGNI

  • DRY (Don't Repeat Yourself, no te repitas): cada dato o regla, en un solo sitio. Es la razón de la regla única de la cuenta del comedor.
  • KISS (Keep It Simple, mantenlo sencillo): la solución más simple que funciona.
  • YAGNI (You Aren't Gonna Need It, no lo vas a necesitar): no programar cosas «por si acaso».

Estos principios chocan entre sí. Abstraer demasiado pronto para no repetir (DRY) complica el código (KISS). Una regla práctica: la primera vez se escribe, la segunda se copia, y a la tercera se saca a una función.

Patrones de diseño: estrategia, observador y fábrica

Un patrón es una solución con nombre a un problema que se repite. En Python, muchos se resuelven con funciones y diccionarios, sin las jerarquías de clases de Java.

  • Estrategia: elegir el algoritmo en el momento de usarlo. Es el diccionario REDONDEOS de arriba, y lo mismo que pasar key= a sorted().
  • Observador: quien quiera, se apunta a un aviso. Es como funcionan los botones de una interfaz gráfica.
class Aviso:
    def __init__(self): self.subs = []
    def suscribir(self, f): self.subs.append(f)
    def emitir(self, *datos):
        for f in self.subs: f(*datos)
nota_nueva = Aviso()
nota_nueva.suscribir(lambda a, n: print(f"Familia de {a}: nueva nota {n}"))
nota_nueva.suscribir(lambda a, n: n < 5 and print(f"Tutoría: revisar a {a}"))
nota_nueva.emitir("Noa", 4.5)
# Familia de Noa: nueva nota 4.5
# Tutoría: revisar a Noa
  • Fábrica: crear un objeto a partir de su nombre, por ejemplo leído de un archivo de configuración. Así se eligen los modelos en muchos proyectos de IA:
MODELOS = {}
def registrar(nombre):
    def deco(cls): MODELOS[nombre] = cls; return cls
    return deco
@registrar("media")
class PredictorMedia:
    def predecir(self, xs): return sum(xs) / len(xs)
@registrar("ultimo")
class PredictorUltimo:
    def predecir(self, xs): return xs[-1]
config = {"modelo": "ultimo"}
print(MODELOS[config["modelo"]]().predecir([5, 6, 8]))         # 8
  • Singleton (una única instancia). Muchas guías lo ponen como el primer patrón, pero en Python casi nunca hace falta: un módulo ya se carga una sola vez, así que basta con poner la configuración en config.py e importarla. Además, un objeto global único dificulta las pruebas, por el mismo motivo que en el principio D.
  • Decorador: ya está en la teoría 14.14, porque Python lo trae en la sintaxis (@).

2. Estructuras de datos avanzadas

Árbol de Fenwick y árbol de segmentos

Las sumas acumuladas responden a la suma de un tramo con una resta, pero si cambia un dato hay que recalcularlas enteras (O(n)). Estas dos estructuras hacen las dos cosas en O(log n):

Sumas acumuladas Árbol de Fenwick Árbol de segmentos
Consultar un tramo O(1) O(log n) O(log n)
Cambiar un dato O(n) O(log n) O(log n)
Qué responde Sumas Sumas (y operaciones que se pueden «deshacer») Sumas, mínimos, máximos…
Código 3 líneas Unas 15 Unas 25

El truco de Fenwick es i & -i, que da el bit más bajo a 1 de i: cada casilla guarda la suma de un bloque cuyo tamaño es ese bit. El árbol de segmentos guarda, en cada nodo, el resultado de su mitad izquierda y su mitad derecha.

import random

class Fenwick:
    def __init__(self, n): self.t = [0] * (n + 1)
    def sumar(self, i, v):                 # a[i] += v
        i += 1
        while i < len(self.t):
            self.t[i] += v; i += i & -i
    def prefijo(self, i):                  # a[0] + ... + a[i]
        i += 1; s = 0
        while i > 0:
            s += self.t[i]; i -= i & -i
        return s
    def tramo(self, l, r):                 # a[l] + ... + a[r]
        return self.prefijo(r) - (self.prefijo(l - 1) if l else 0)

# --- Árbol de segmentos (versión iterativa): también vale para mínimos o máximos
class Segmentos:
    def __init__(self, a, op=min, neutro=float("inf")):
        self.n, self.op, self.neutro = len(a), op, neutro
        self.t = [neutro] * self.n + list(a)
        for i in range(self.n - 1, 0, -1):
            self.t[i] = op(self.t[2 * i], self.t[2 * i + 1])
    def cambiar(self, i, v):
        i += self.n; self.t[i] = v
        while i > 1:
            i //= 2; self.t[i] = self.op(self.t[2 * i], self.t[2 * i + 1])
    def consulta(self, l, r):              # sobre a[l:r]
        res, l, r = self.neutro, l + self.n, r + self.n
        while l < r:
            if l & 1: res = self.op(res, self.t[l]); l += 1
            if r & 1: r -= 1; res = self.op(res, self.t[r])
            l //= 2; r //= 2
        return res

# Plazas libres en cada aula a lo largo del día (inventado)
plazas = [3, 0, 5, 2, 7, 1, 4, 6]
fw = Fenwick(len(plazas))
for i, x in enumerate(plazas): fw.sumar(i, x)
st = Segmentos(plazas)
print(fw.tramo(2, 5), st.consulta(2, 6))       # 15 1
fw.sumar(5, +3); plazas[5] += 3; st.cambiar(5, plazas[5])
print(fw.tramo(2, 5), st.consulta(2, 6))       # 18 2

# Comprobación contra la fuerza bruta, con 2000 operaciones al azar
random.seed(3)
a = [random.randint(0, 9) for _ in range(200)]
fw, st = Fenwick(200), Segmentos(a)
for i, x in enumerate(a): fw.sumar(i, x)
ok = True
for _ in range(2000):
    if random.random() < 0.5:
        i, v = random.randrange(200), random.randint(0, 9)
        fw.sumar(i, v - a[i]); a[i] = v; st.cambiar(i, v)
    else:
        l = random.randrange(200); r = random.randrange(l, 200)
        ok &= fw.tramo(l, r) == sum(a[l:r + 1]) and st.consulta(l, r + 1) == min(a[l:r + 1])
print("coincide con la fuerza bruta:", ok)
# 15 1
# 18 2
# coincide con la fuerza bruta: True

Las plazas libres de las aulas 2 a 5 suman 15, y el mínimo es 1. Al liberar 3 plazas en el aula 5, las dos estructuras se actualizan sin recalcularlo todo. Comprobarlas contra la fuerza bruta con miles de operaciones al azar es la forma de saber que no tienen fallos en los bordes.

¿Cuándo hacen falta? Cuando hay muchos cambios y muchas consultas mezclados: concursos de programación, motores de juegos, bases de datos. Para analizar datos que no cambian, cumsum de NumPy o Pandas es suficiente.

Trie: autocompletar por prefijos

Un trie guarda palabras letra a letra en un árbol de diccionarios. Buscar todas las palabras que empiezan por un prefijo cuesta lo que mide el prefijo, no lo que mide el diccionario:

def trie_de(palabras):
    raiz = {}
    for p in palabras:
        nodo = raiz
        for c in p: nodo = nodo.setdefault(c, {})
        nodo["$"] = True
    return raiz
def completar(raiz, prefijo):
    nodo = raiz
    for c in prefijo:
        if c not in nodo: return []
        nodo = nodo[c]
    res, pila = [], [(nodo, prefijo)]
    while pila:
        n, p = pila.pop()
        for c, hijo in n.items():
            if c == "$": res.append(p)
            else: pila.append((hijo, p + c))
    return sorted(res)
t = trie_de(["biblioteca", "bioloxía", "bicicleta", "física", "filosofía"])
print(completar(t, "bi"), completar(t, "fil"), completar(t, "x"))
# ['biblioteca', 'bicicleta', 'bioloxía'] ['filosofía'] []

Los tokenizadores de los modelos de lenguaje (UD4) usan estructuras parecidas para encontrar el trozo de palabra más largo que conocen.

Listas enlazadas

Cada nodo guarda un valor y una referencia al siguiente. En lenguajes como C se usan para insertar y borrar en O(1) en mitad de una secuencia. En Python casi nunca hacen falta: list va mejor para casi todo y collections.deque sirve para las colas (teoría 14.12). Siguen saliendo en entrevistas (darle la vuelta, detectar un ciclo con un puntero lento y otro rápido) porque obligan a pensar con referencias.

3. Más algoritmos de grafos

La página de Algoritmos explica la búsqueda en anchura, Dijkstra y A*, que son los del currículo (búsqueda en la UD1). Estos tres resuelven otros problemas.

Algoritmo Problema Coste Limitación
Kruskal (o Prim) Unir todos los puntos con el mínimo total (árbol de expansión mínima) O(E log E) Grafo no dirigido
Bellman-Ford Caminos más cortos desde un origen, con pesos negativos O(V·E) Detecta ciclos negativos, pero no puede resolverlos
Floyd-Warshall Caminos más cortos entre todas las parejas O(V³) Solo para grafos pequeños: con 400 nodos son 64 millones de pasos (unos 3 s en Python puro)

Kruskal: cablear las aulas con el mínimo de metros. Se recorren las conexiones de la más corta a la más larga y se coge cada una si une dos grupos que aún no estaban conectados. Es la Union-Find de la teoría 14.12:

aristas = [(12, "Conserjería", "Biblioteca"), (8, "Conserjería", "Aula 1"), (5, "Aula 1", "Aula 2"),
           (9, "Aula 2", "Laboratorio"), (7, "Biblioteca", "Laboratorio"), (15, "Aula 1", "Laboratorio"),
           (6, "Biblioteca", "Aula 2")]
def kruskal(aristas):
    padre = {}
    def raiz(x):
        padre.setdefault(x, x)
        while padre[x] != x:
            padre[x] = padre[padre[x]]; x = padre[x]
        return x
    elegidas = []
    for m, a, b in sorted(aristas):                # de la más corta a la más larga
        if raiz(a) != raiz(b):                      # solo si une dos grupos distintos
            padre[raiz(a)] = raiz(b); elegidas.append((a, b, m))
    return elegidas
cables = kruskal(aristas)
print(cables, sum(m for *_, m in cables))
# [('Aula 1', 'Aula 2', 5), ('Biblioteca', 'Aula 2', 6), ('Biblioteca', 'Laboratorio', 7),
#  ('Conserjería', 'Aula 1', 8)] 26

Bellman-Ford: una prueba de la gymkhana que da tiempo extra (peso −3). Dijkstra no sirve con pesos negativos; Bellman-Ford sí, y además avisa si hay un ciclo negativo: una vuelta que, repetida, haría el camino infinitamente corto.

INF = float("inf")

def bellman_ford(nodos, aristas, origen):
    dist = {n: INF for n in nodos}; dist[origen] = 0
    for _ in range(len(nodos) - 1):
        for u, v, w in aristas:
            if dist[u] + w < dist[v]: dist[v] = dist[u] + w
    for u, v, w in aristas:                         # una vuelta más: si aún mejora, hay ciclo negativo
        if dist[u] + w < dist[v]: return None
    return dist
nodos = ["salida", "A", "B", "meta"]
pruebas = [("salida", "A", 4), ("salida", "B", 5), ("A", "B", -3), ("A", "meta", 6), ("B", "meta", 2)]
print(bellman_ford(nodos, pruebas, "salida"))
print(bellman_ford(nodos, pruebas + [("B", "A", 1)], "salida"))   # A→B→A suma -2: ciclo negativo
# {'salida': 0, 'A': 4, 'B': 1, 'meta': 3}
# None

Floyd-Warshall: la tabla de distancias entre todos los edificios. Para cada edificio intermedio k, se comprueba si pasar por él acorta el camino entre i y j:

INF = float("inf")
ed = ["Conserjería", "Biblioteca", "Gimnasio", "Comedor"]
d = [[0, 3, INF, 7], [3, 0, 2, INF], [INF, 2, 0, 1], [7, INF, 1, 0]]
n = len(d)
for k in range(n):
    for i in range(n):
        for j in range(n):
            d[i][j] = min(d[i][j], d[i][k] + d[k][j])
for e, fila in zip(ed, d): print(f"{e:12s}", fila)
# Conserjería  [0, 3, 5, 6]
# Biblioteca   [3, 0, 2, 3]
# Gimnasio     [5, 2, 0, 1]
# Comedor      [6, 3, 1, 0]

Los tres resultados coinciden con los de NetworkX (nx.minimum_spanning_tree da 26 y nx.single_source_bellman_ford_path_length, las mismas distancias). En un proyecto se usa la librería; programarlos a mano sirve para entender qué hacen.

4. Dos técnicas de entrevista

Kadane: el mejor tramo seguido, con números negativos. En cada paso se decide si conviene seguir el tramo o empezar uno nuevo aquí. Es O(n), frente a O(n²) de probar todos los tramos:

cambios = [3, -5, 4, -1, 2, 6, -8, 3]          # variación diaria de socios del club de ajedrez
def kadane(xs):
    actual = mejor = xs[0]; ini = mejor_ini = mejor_fin = 0
    for i in range(1, len(xs)):
        if xs[i] > actual + xs[i]:
            actual, ini = xs[i], i               # empezar de nuevo aquí
        else:
            actual += xs[i]                      # seguir el tramo
        if actual > mejor:
            mejor, mejor_ini, mejor_fin = actual, ini, i
    return mejor, mejor_ini, mejor_fin
bruta = max((sum(cambios[i:j + 1]), i, j) for i in range(len(cambios)) for j in range(i, len(cambios)))
print(kadane(cambios), bruta)
# (11, 2, 5) (11, 2, 5): del día 2 al 5 el club ganó 11 socios

Muestreo de embalse (reservoir sampling): k elementos al azar de un flujo que no cabe en memoria. El elemento número i (contando desde 0) entra en la muestra con probabilidad k/(i + 1). Al final, todos tienen la misma probabilidad, sin haber guardado el flujo entero:

import random, collections

def embalse(flujo, k, rng):
    muestra = []
    for i, x in enumerate(flujo):
        if i < k:
            muestra.append(x)
        else:
            j = rng.randrange(i + 1)             # 0..i
            if j < k: muestra[j] = x
    return muestra
rng = random.Random(5)
cuenta = collections.Counter()
for _ in range(30_000):
    cuenta.update(embalse(range(10), 3, rng))
print(sorted(round(c / 30_000, 3) for c in cuenta.values()))   # cada elemento, cerca de 3/10
# cada uno de los 10 elementos sale entre el 29,7 % y el 30,4 % de las veces: el 30 % esperado

Sirve, por ejemplo, para guardar una muestra justa de los mensajes que pasan por un servidor, o de las filas de un archivo de 100 GB.

5. Bases de datos: índices y normalización

Índice. Sin índice, buscar los préstamos de un alumno obliga a leer la tabla entera (SCAN). Un índice es una estructura ordenada (un árbol B) que permite ir directamente (SEARCH). A cambio, ocupa espacio y cada inserción es algo más lenta, porque hay que actualizarlo:

import sqlite3, random, time
con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE prestamos (id INTEGER PRIMARY KEY, alumno INTEGER, libro INTEGER, dia INTEGER)")
random.seed(1)
con.executemany("INSERT INTO prestamos (alumno, libro, dia) VALUES (?, ?, ?)",
                [(random.randrange(5000), random.randrange(20000), random.randrange(365)) for _ in range(500_000)])
q = "SELECT COUNT(*) FROM prestamos WHERE alumno = ?"
def medir():
    t = time.perf_counter()
    for a in range(200): con.execute(q, (a,)).fetchone()
    return (time.perf_counter() - t) / 200 * 1000
print(con.execute("EXPLAIN QUERY PLAN " + q, (7,)).fetchall()[0][-1], f"{medir():.2f} ms")
con.execute("CREATE INDEX idx_alumno ON prestamos(alumno)")
print(con.execute("EXPLAIN QUERY PLAN " + q, (7,)).fetchall()[0][-1], f"{medir():.3f} ms")
t = time.perf_counter()
con.executemany("INSERT INTO prestamos (alumno, libro, dia) VALUES (?, ?, ?)", [(1, 2, 3)] * 100_000)
print(f"insertar 100 000 con índice: {time.perf_counter() - t:.2f} s")
con.execute("DROP INDEX idx_alumno")
t = time.perf_counter()
con.executemany("INSERT INTO prestamos (alumno, libro, dia) VALUES (?, ?, ?)", [(1, 2, 3)] * 100_000)
print(f"insertar 100 000 sin índice: {time.perf_counter() - t:.2f} s")
# SCAN prestamos 14.49 ms
# SEARCH prestamos USING COVERING INDEX idx_alumno (alumno=?) 0.004 ms
# insertar 100 000 con índice: 0.09 s
# insertar 100 000 sin índice: 0.06 s

Con medio millón de filas inventadas, la consulta pasa de unos 14 ms a unos 0,004 ms. EXPLAIN QUERY PLAN dice si se usa el índice: es lo primero que se mira cuando una consulta va lenta.

Normalización. Consiste en no guardar el mismo dato en varios sitios. Si cada préstamo guarda también el nombre y el curso del alumno, y el alumno cambia de curso, hay que cambiarlo en cientos de filas, y si se olvida una, la base de datos se contradice. La solución es separar en tablas (alumnado, libros, prestamos) unidas por claves, como en el merge de datos 3.4. Las «formas normales» (1FN, 2FN, 3FN) son las reglas formales para hacerlo. A veces se desnormaliza a propósito, para que las consultas de lectura sean más rápidas.
