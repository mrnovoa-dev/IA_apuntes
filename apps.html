Apps y juegos con Python

Diez proyectos para pasar de los ejercicios sueltos a programas completos que alguien puede usar: cinco básicos con lo visto en la UD2 (entrada y salida, condiciones, bucles, listas, funciones) y cinco intermedios que añaden internet, archivos, datos y web. Cada proyecto puede ser una tarea, una práctica de dos o tres sesiones o una pieza del portafolio del alumnado.

La idea parte de un carrusel de Instagram (@analyticswithsingh, marcado como «contenido generado con IA») con diez proyectos y su código. El código de esas imágenes tiene fallos —uno de ellos impide que el programa arranque—, así que aquí los enunciados son propios y el último reto, el P11, consiste en encontrar esos fallos.

Cómo trabajar cada proyecto:

  1. Leer el enunciado y escribir en papel los pasos (qué pide el programa, qué decide, qué muestra). Ver algoritmia.
  2. Hacer primero los requisitos mínimos; solo cuando funcionan, las ampliaciones.
  3. Probar los casos raros: texto donde se espera un número, cero, listas vacías, sin conexión…
  4. Separar la lógica (funciones que calculan y devuelven) de la interfaz (input y print): así se puede probar y, más adelante, poner una ventana o una web encima (sección 13).

Proyectos básicos

P1 · Calculadora

Una calculadora de consola que repite hasta que la persona decide salir.

Requisitos mínimos

  • Muestra un menú con las cuatro operaciones y una opción para salir.
  • Pide dos números y muestra el resultado; admite decimales con coma (2,5) o con punto.
  • No se rompe si se escribe una letra donde va un número: avisa y vuelve a preguntar.
  • Dividir entre 0 da un mensaje, no un error de Python.
  • La operación está en una función calcular(a, b, op) que devuelve el resultado.

Ampliaciones: potencia y raíz; historial de las últimas operaciones; mostrar 6 en lugar de 6.0 cuando el resultado es entero.

Teoría: 2.5 Entrada, salida y formato, 3 Estructuras de control, 4 Funciones.

P2 · Adivina el número

El ordenador piensa un número del 1 al 20 y la persona tiene cinco intentos para adivinarlo.

Requisitos mínimos

  • Número secreto con random.randint.
  • Después de cada intento dice «más alto» o «más bajo» y cuántos intentos quedan.
  • Al acertar, dice en cuántos intentos; si se acaban, revela el número.
  • Si se escribe algo que no es un número, o fuera del rango, avisa sin gastar un intento.

Ampliaciones: niveles de dificultad (rango y número de intentos); jugar otra vez; guardar el récord en un archivo; el juego al revés: tú piensas el número y el ordenador lo adivina en, como mucho, 5 preguntas (búsqueda binaria).

Teoría: 3 Estructuras de control, 5.7 Módulos útiles.

P3 · Lista de tareas

Una agenda de tareas en la consola que se guarda en un archivo, para que no se pierda al cerrar.

Requisitos mínimos

  • Menú: añadir, ver, marcar como hecha, borrar y salir.
  • Cada tarea es un diccionario {"texto": ..., "hecha": False} dentro de una lista.
  • Al ver la lista aparecen numeradas desde 1 y con una marca si están hechas.
  • Elegir un número que no existe da un aviso, no un IndexError.
  • Las tareas se guardan en tareas.json y se cargan al empezar.

Ampliaciones: fecha límite y ordenar por fecha; prioridad; buscar por texto; una versión con ventana usando Tkinter o con Streamlit (13.3).

Teoría: 5.4 Listas a fondo, 5.9 Tablas como listas de diccionarios.

P4 · Generador de contraseñas

Genera contraseñas aleatorias seguras y dice cómo de fuertes son.

Requisitos mínimos

  • La persona elige la longitud (mínimo 8) y si quiere símbolos.
  • La contraseña tiene al menos una minúscula, una mayúscula y un número (y un símbolo, si se pidió).
  • Usa el módulo secrets, no random (y explica por qué en un comentario).
  • Una función fuerza(clave) puntúa una contraseña cualquiera: «débil», «media», «fuerte»…

Ampliaciones: generar varias de golpe; evitar caracteres que se confunden (l, 1, O, 0); contraseñas de palabras («piedra-río-lápiz-nube»), más fáciles de recordar y igual de seguras si son largas.

Teoría: 2.6 Cadenas a fondo, 5.6 Comprensiones.

P5 · Piedra, papel o tijera

El clásico contra el ordenador, al mejor de tres.

Requisitos mínimos

  • Acepta Piedra, PIEDRA o piedra; si se escribe otra cosa, avisa y repite la ronda.
  • Las reglas están en un diccionario (qué gana a qué), no en un if larguísimo.
  • Lleva el marcador y termina cuando alguien llega a 2 victorias.

Ampliaciones: la versión con lagarto y Spock (5 opciones: con el diccionario solo cambian los datos); estadísticas de qué saca más la persona; un ordenador «listo» que juega lo que gana a lo que más has sacado.

Teoría: 5 Estructuras de datos.

Proyectos intermedios

P6 · App del tiempo

Pide una localidad y muestra el tiempo actual y la previsión de tres días, con un aviso si hay que llevar paraguas.

Requisitos mínimos

  • Usa la API gratuita de Open-Meteo, que no necesita clave para uso no comercial: primero el buscador de localidades (geocodificación) y después la previsión.
  • Muestra temperatura, estado del cielo en castellano (los códigos numéricos se traducen con un diccionario) y viento.
  • Para cada día: mínima, máxima y lluvia en mm; si son 1 mm o más, «lleva paraguas».
  • Si la localidad no existe o no hay conexión, da un mensaje claro en lugar de un error.

Ampliaciones: comparar varias localidades (Marín, Pontevedra, Vigo); gráfico de las temperaturas de la semana; guardar cada consulta en un CSV y, al cabo de un mes, analizarlo con Pandas.

Teoría: Análisis de datos 1.1–1.3 (APIs y JSON), 14.10 Automatización.

P7 · Recolector de datos web

Un programa que recoge datos de una web y los guarda en una tabla para analizarlos.

Requisitos mínimos

  • Trabaja con quotes.toscrape.com, una web hecha para practicar scraping: frases, autores y etiquetas, repartidas en varias páginas.
  • Antes de empezar, comprueba robots.txt con urllib.robotparser.
  • Extrae cada cita con BeautifulSoup y sigue el enlace «Next» hasta un máximo de páginas, con una pausa de 1 segundo entre peticiones.
  • Guarda el resultado en citas.csv y muestra los cinco autores con más citas.

Ampliaciones: las etiquetas más frecuentes; books.toscrape.com (precios y valoraciones, otra web de práctica); un gráfico de barras.

Antes de recoger datos de otra web: leer sus condiciones de uso y su robots.txt, no recoger datos personales y preferir una API si existe. Ver Análisis de datos 1.4.

P8 · Control de gastos

Una aplicación para apuntar gastos personales y ver en qué se va el dinero.

Requisitos mínimos

  • Añade gastos (fecha, concepto, categoría, importe) a gastos.csv, separado por ;.
  • Solo acepta categorías de una lista fija e importes positivos.
  • Resumen con Pandas: total por categoría (de mayor a menor) y por mes.
  • Avisa si un mes supera un presupuesto.
  • Dos gráficos en una figura: barras por categoría y línea por mes, guardados en gastos.png.

Ampliaciones: menú de consola o interfaz con Streamlit; ingresos además de gastos (saldo); importar el CSV que exporta un banco; la media diaria de cada mes.

Teoría: 7.3 Pandas a fondo, 8 Matplotlib.

P9 · Chatbot

Un asistente de conversación para la asignatura, en dos versiones: con reglas y con un modelo de lenguaje.

Requisitos mínimos

  • Versión 1, con reglas: responde a saludos, horario, entregas y evaluación buscando palabras clave. Entiende mayúsculas, tildes y algo de gallego («Boas», «Cando hai clase?»).
  • Si no entiende, lo dice y sugiere qué preguntar.
  • Termina al escribir «salir».
  • Versión 2, con IA: envía la conversación a un modelo de lenguaje y guarda el historial para que «recuerde» lo anterior, con un límite de mensajes.
  • Si el modelo no responde, vuelve a las reglas en lugar de romperse.

Ampliaciones: leer las respuestas de un archivo JSON; un «mensaje de sistema» que fije el tono; versión con Streamlit (st.chat_input).

Sobre claves y datos: una clave de API nunca va en el código ni se sube a GitHub; se guarda en una variable de entorno (os.environ["NOMBRE"]). Muchos servicios de IA exigen tener 18 años: en clase es preferible un modelo local (por ejemplo, con Ollama), que no necesita clave ni envía la conversación fuera del ordenador.

Teoría: 14.8 IA generativa y LLM, UD4 sección 8.

P10 · Web portafolio

Una pequeña web con Flask para enseñar los proyectos anteriores.

Requisitos mínimos

  • Página de inicio con la lista de proyectos y una página por proyecto (/proyecto/calculadora, /proyecto/tiempo…).
  • Los datos de los proyectos están en un diccionario de Python; las páginas se generan con plantillas (templates/), sin repetir HTML.
  • Una plantilla base con la cabecera, que heredan las demás.
  • Un proyecto que no existe da una página de error 404 propia.
  • Una hoja de estilos en static/ y que se vea bien en el móvil.

Ampliaciones: formulario de contacto (request.form); los proyectos en un archivo JSON; capturas de pantalla de cada proyecto.

¿Hace falta Flask? Para una web que solo muestra información, no: basta con HTML y CSS publicados gratis en GitHub Pages, como esta misma web. Flask tiene sentido cuando la web hace algo: un formulario, una consulta a una API, un modelo de IA (13.7).

Teoría: 13.4 Aplicaciones web.

Rúbrica común

Sirve para cualquiera de los proyectos (10 puntos):

Criterio Excelente Suficiente Insuficiente
Funciona (4) Cumple todos los requisitos mínimos y alguna ampliación Cumple los requisitos mínimos Falta algún requisito o no arranca
Robustez (2) No se rompe con entradas raras, ceros, listas vacías ni sin conexión Controla los casos más evidentes Se cierra con un error ante una entrada inesperada
Código (2) Funciones con un solo trabajo, nombres claros, lógica separada de input/print Funciones y nombres razonables Todo seguido, nombres como a, x2, código repetido
Explicación (2) Sabe explicar cada parte, qué probó y qué mejoraría; si usó IA, dice para qué y qué cambió Explica el funcionamiento general No sabe explicar su propio código

Si se ha usado IA para ayudarse, se indica en un comentario al principio del programa. La explicación oral o escrita es lo que demuestra que el código se entiende.
